**SQ-01 `/api/chat` moving unchanged behind `/terminal`** (T-30–T-35, SEC-30–35; audit F-03, F-19)
Assessment: moving it unchanged adds **no new** risk compared with production today. But the route is anonymous and scriptable, has no rate limit, size cap or timeout, logs visitor messages, discloses env flags on `GET`, and builds its system prompt from the request body. The new home will bring more traffic to the domain. **Unchanged is tolerable only for a short time and only with the platform controls in (a).** Prompt injection (T-31) remains in every option except (c) until "Ask Tijo".
- (a) Move unchanged. Add zero-code platform controls only: a Vercel Firewall rate-limit rule on `/api/chat` (10 req / 60 s / IP, if your plan has it), a Groq usage limit and alert, and the Groq key scoped to Production.
- (b) **(rec)** (a) plus a minimal guard in `app/api/chat/route.ts` only (about 40 lines; the terminal UI is unchanged): remove `GET`, drop the `debug` field, generic error body, 8 KB body cap, `message` 1–1000 chars, 10 s Groq timeout → 504, no message text in logs. Adds proposed TERM-AC-07 to TERM-AC-10.
- (b+) (b) plus the one-file chat XSS fix (`ChatMessages.tsx:73`: render `**bold**` as React nodes). This is a small change to terminal UI code.
- (c) Disable the chat backend now (the route returns 503; the terminal shows its existing fallback text) until "Ask Tijo".
- (d) Move unchanged with no controls (not recommended).

- (d) No privacy notice (not recommended).

**SQ-03 HSTS** (SEC-01, SEC-45)
- (a) **(rec)** `max-age=63072000; includeSubDomains`, no preload.

Dead copies (`EnhancedChatAgent.tsx`, `components/PrivacyPolicy.tsx`, `shared/schemas/chat.ts`, `features/terminal/…`, the hidden block in `app/layout.tsx`) disappear anyway with the purge and the new layouts.

No logic changes. Add a gate that scans the `/terminal` build output with the same patterns as CONT-AC-14. Similarity stays ≥ 90% for PLAT-AC-10 except for the edited lines (record the exception).
